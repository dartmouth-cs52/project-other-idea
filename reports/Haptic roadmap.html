From a demo to the Fortune 500

The vision: anyone can ask any software how to do something and be shown where to click, on the live page, in about a second. No tours to write. No support ticket.

  • Now

    Guides

    Points to the next control and waits for the person to click it.

  • Later

    Answers

    Replies to questions that need words, from the company's help docs.

  • Later still

    Acts

    Does the steps for the person, when they ask it to.

Straight talk. Large companies are stage 5 of 5, and Haptic is in stage 1. Today it runs on a laptop and no real model has been tested on it. Your own website says "Is Haptic ready for enterprise? Not yet", and that is still true.

The slowest item on the whole path is the outside security audit in stage 4. It watches how you work over a period, usually three to twelve months, so it cannot be rushed at the end. Everything else can move faster than that.

The path

Five stages. Each one ends with a test. Don't start the next stage until the test is passed.

  1. 1

    Make guides work

    You are here

    Guides are right and quick on real sites, not just the demo.

    Build

    • Test set of 57 steps with right answers
    • "Not that one" message after a wrong click
    • Put the server online, so the script has something to talk to
    • Run the test set on three models and pick the fastest one that is still right
    • Move the pointer the moment the model names the button
    • Record test steps from the real sites you are working with
    • Merge this work into main

    Move on when

    Guides pass the mark you set on three real sites, and the pointer moves in about one second.

    You still have to set the mark. A sensible start: the first pointer is right nine times in ten.

  2. 2

    First five companies, by hand

    Next

    Small companies where the person who signs up can add the script themselves. You set each one up on a call.

    Build

    • One page that says what the script reads, hides and sends
    • An install page: the script, a "send to my developer" button, and a live "connected" check
    • A log of every step, to see which questions repeat and which pointers are wrong
    • Keep the Request access form. No signup yet

    Move on when

    Five companies have Haptic live for their own users, and you have written down where each one got stuck.

    You now know your install rate, which nobody publishes.

  3. 3

    Sign up without us, and remember

    A company goes from signup to live without talking to you, and Haptic gets faster the more it is used.

    Build

    • Accounts and a dashboard
    • A preview that only the company's admin can see, before it goes live for everyone
    • Memory: routes a person has confirmed, so a repeat question needs no model
    • A reader for public sites that are built with JavaScript
    • Pricing
    • Start the security audit paperwork now, because it is the slow part

    Move on when

    Companies are paying, they set themselves up, and repeat questions are answered with no model call.

  4. 4

    Ready for a security review

    A large company's security team can say yes. This stage is paperwork and controls more than product.

    Build

    • An outside security audit (SOC 2): first the quick version, then the one that runs for months
    • Hired testers who try to break in, and their report
    • A data contract, and a list of every company that touches customer data
    • Sign in with the customer's own company login, with roles and a record of who changed what
    • A locked version of the script, and a way to serve it from the customer's own address
    • Uptime tracking, a status page, and an off switch per customer

    Move on when

    You can answer a security questionnaire without scrambling, and two or three mid-size companies will vouch for you.

  5. 5

    Fortune 500

    Start with one team and one app inside one large company, not the whole company.

    Build

    • The contracts and insurance their buying team requires
    • A pilot plan: one app, their staff first, a number that proves it worked
    • Someone whose job is that customer
    • Proof it holds up under their traffic

    Done when

    The first signed pilot is live and its number moved: fewer support tickets, or tasks finished faster.

What to do next, in order

The first three are waiting on you.

  1. Get an API key and say yes to about ten dollars.Then the test set can run on real models. Until it does, nobody knows which model to use.
  2. Choose where the server lives and what its address is.The address is permanent once a customer pastes the script. My pick: Cloudflare, at widget.joinhaptic.com.
  3. Name the real sites you are working with.Test steps recorded on them replace guesses from the demo app.
  4. Run the comparison and pick a model.Fastest one that clears your mark.
  5. Put the server online and move the pointer early.Then try each real site and write down what breaks.

What a large company will ask

Six questions that end deals when the answer is "not yet". Each maps to stage 4.

  • Has an outside firm audited your security?They want the report, not a promise.
  • What exactly does your script read on our pages?Haptic has a good answer: names of buttons and fields, never what people type.
  • Do you train AI on our data?Decide the answer and put it in the contract.
  • Can our people sign in with our company login?And can we see who changed what?
  • Can we pin the script and turn it off ourselves?A script that updates itself is a risk to them.
  • Who else uses it?They want names of companies like them.

What could change this plan

Still unknown

  • Whether a small, fast model is right often enough on real apps
  • How often people ask the same question, which decides if memory is worth building
  • How many buyers can install the script without an engineer
  • Whether logging guided sessions needs the user's consent

Not on the path yet, on purpose

  • Training your own model. It needs thousands of real steps, which stage 2's log starts to collect
  • A public benchmark on the website. A score on your own demo app convinces nobody
  • Answers and Acts. Guides have to be right first

How sure: stages 1 and 2 come from the research report and from the code as it is today. The lists in stages 4 and 5 are what large buyers commonly require and were not checked against any one company's process. The order of stages 3 to 5 should be revisited after the first five companies.
